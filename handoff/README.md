# Handoff

Handoff is a private locker. An operator invites someone, they drop files for one workspace, and a scan worker marks each file clean, rejected, or held. Handoff is not part of any client's product. It does not import into a client's app, and it does not share a database, cookie, or package with the operations site.

## One region

Keep the app, the database, and the file bucket in one region. Do not replicate a workspace's files to a second region.

## Local setup

```bash
cd handoff
npm install
npm test
npm run dev
```

`npm test` runs the unit suite, including workspace isolation. Those tests apply `migrations/0001_handoff.sql` through `migrations/0009_conversations.sql` to Node's built-in SQLite. `npm run test:db` runs the same isolation file. No Docker or hosted database is required.

Copy `.env.example` to `.env.local` for the Next app and to `.dev.vars` for Wrangler. Leave secrets out of git. Local runs that are not inside a Worker store records in `.data/handoff.db`.

Worker `handoff` wakes the HQ agent on three schedules: every 15 minutes for open work or new files, every hour when a cloud run is still open, and Monday at 08:00 UTC for a client status note. The body is JSON with `organizationId`, `reason`, and `sentAt`. Header `x-handoff-signature` is HMAC-SHA256 of that raw body using `AGENT_WAKE_SECRET`. A signature that does not match, or a `sentAt` older than five minutes, is refused by the agent. A failed wake writes activity `agent.wake_failed` and is tried again next cycle. A paused or archived client is skipped. Set `AGENT_URL` and `AGENT_WAKE_SECRET` on worker `handoff`. Leave the secret out of git. Worker `handoff-agent` is class `ClientAgent`, one instance per organization. `POST /wake` checks that signature and starts the instance. The brief names the `.cursor/skills` paths a later Cursor run should follow. A brief approval plans one task and one draft per piece, and a `work` wake runs one skill step, writes the result, and schedules the next step. Production leaves `MCP_PORTAL_URL` empty until that portal exists. Staff chat lives at `/chat` on the HQ host and talks to Durable Object `HqChat`. Client mail is answered by `email()` on `handoff-agent` after a routing rule exists. A sender must match a contact or a live member, and the topmost `Authentication-Results` header must show DMARC pass for the From domain or a DKIM pass signed by that domain. Replies to one message stay in one thread and add to one open request. A thread gets ten replies an hour; the eleventh says a person will pick it up, and later messages are kept with no reply. Slack events post to `https://agent.abra-ca-dabra.app/channels/slack`; staff link a channel with the chat tool `link_slack_channel`. An approved client request or `add_work` saves a brief version. When the client's `brief_approval` is `staff`, approving the card approves that version and wakes the agent with `brief_changed`; when it is `client`, the version waits as a draft. `HQ_CHAT_SECRET`, `CLIENT_CHANNEL_SECRET`, and the Slack secrets stay off the worker vars.

## Writing style

All text people see (screens, emails, error messages) is written in short, plain sentences at about a grade 5 reading level. Say "space" (not workspace or locker), "storage limit" (not quota), "admin" (not super-admin) and "delete" (not purge). Code names, routes, status values and database fields keep their technical names.

## Finished work

Staff add finished work on a project page, then open it at `/deliverables/[id]`. Send to the client publishes the current round. Pull from the repo reads a manifest such as `deliverables/social-preview/manifest.json` and the picture and video files listed in it. The client sees sent work at `/w/[slug]/work` and can approve a piece or ask for changes. Pictures and videos load through `GET /api/deliverables/[deliverableId]/items/[itemId]/media/[role]`. A caller who cannot see that space gets an empty 404. A later draft round does not replace what the client already sees until it is sent.
