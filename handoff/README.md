# Handoff

Handoff is a private locker. An operator invites someone, they drop files for one workspace, and a scan worker marks each file clean, rejected, or held. Handoff is not part of any client's product. It does not import into a client's app, and it does not share a database, cookie, or package with the operations site.

## One region

Keep the app, the database, and the file bucket in one region. Do not replicate a workspace's files to a second region.

## Local setup

```bash
cd handoff
npm install
npm test
npm run dev
```

`npm test` runs the unit suite, including workspace isolation. Those tests apply `migrations/0001_handoff.sql` through `migrations/0005_crm.sql` to Node's built-in SQLite. `npm run test:db` runs the same isolation file. No Docker or hosted database is required.

Copy `.env.example` to `.env.local` for the Next app and to `.dev.vars` for Wrangler. Leave secrets out of git. Local runs that are not inside a Worker store records in `.data/handoff.db`.

## Cloudflare

The app runs on Cloudflare Workers through OpenNext (`@opennextjs/cloudflare`). Locker records live in D1 database `handoff`, bound as `DB` in `wrangler.jsonc`. Each migration file is also copied into `src/db/migration-sql.ts`. The worker creates a missing table from that copy, because it has no migrations folder of its own. File bytes go to R2 bucket `handoff` in ENAM through multipart uploads. The malware scan runs in a Cloudflare Container from `worker/Dockerfile`, because a Worker isolate cannot run `clamd`. `npm run worker` claims `uploaded` files with a SQLite compare-and-set, reads each object once, and writes `clean`, `rejected`, `held`, or a retry. A closed batch window marks leftover `pending` and `uploading` files `failed` and emails the uploader once. Rejected and failed object bytes older than 14 days are deleted; the row and its reason stay. The first clean file in a named request marks that request `received`. The same pass queues product email (operators when a batch is ready, the uploader and operators when a file is rejected or held) and sends it through Resend. Each message has one Handoff page link from `HANDOFF_APP_ORIGIN` and the scanner finding name. A repeated event does not send again. A weekly digest goes only to client owners when `request_digest` is on. `GET /health` on `$PORT` reports whether `clamd` answers. Production exits when `clamd` is unreachable and when `HANDOFF_ALLOW_UNSCANNED=1`. The home page does not send a magic link. Sign in at `/login` with username `admin` and `HANDOFF_ADMIN_PASSWORD`. A matching password signs in `studio@handoff.local` as the owner of the Strongfoam space (`/w/strongfoam`) and as the admin. A wrong password does not open a session. On the client host that sign-in lands on `/`. On `hq` it lands on `/spaces`. Old `/admin` links redirect to `hq` `/spaces`. A second sign-in reuses that user and space. If the older Northwind Studio row is still there, that open renames it in place to Strongfoam and keeps its files. The owner sees a share link (`/share/[token]`, stored in `upload_shares`). Opening it signs the visitor in as a member of that space, not the owner, and sends them to the upload page. A second visit reuses that guest. Anyone with the link can add files. No email is sent. A bad link returns home with `notice=share`. Invite pages still ask for a magic link. Those links go out through Resend and the session lives in D1 (`users`, `magic_links`, and `sessions` in `migrations/0002_sessions.sql`). A link is sent only for an allow-listed bootstrap address while staff is empty, or for a live staff, membership, or active-workspace invite. The form does not say which case applied. `assertProductionEnv` checks for `RESEND_API_KEY` and is not called when the Worker starts. Invite magic links fail closed until that key and `HANDOFF_FROM_EMAIL` are set. `HANDOFF_ALLOW_UNSCANNED=1` is refused when `NODE_ENV=production`.

The public client host is https://handoff.abra-ca-dabra.app on worker `handoff`. The workers.dev preview still answers. `GET /api/health` returns `{ database: "d1", ok: true }` for a signed-out caller. Worker secrets are `HANDOFF_SIGNING_SECRET`, `HANDOFF_APP_ORIGIN` (`https://handoff.abra-ca-dabra.app`), and `HANDOFF_ADMIN_PASSWORD`. `RESEND_API_KEY` and `HANDOFF_FROM_EMAIL` are unset, so invite mail cannot send. Sign in as `admin` with that password. The sign-in page fills in the username. Spaces around the password are ignored. That sign-in is the admin. Staff tools are at `https://hq.abra-ca-dabra.app/spaces` on worker `handoff-hq` (`npm run deploy:hq`, config `wrangler.hq.jsonc`). The workers.dev staff host still answers. That worker shares D1 and R2 with `handoff`. Both workers set `HANDOFF_HQ_ORIGIN` to `https://hq.abra-ca-dabra.app` and `HANDOFF_APP_ORIGIN` to `https://handoff.abra-ca-dabra.app`. `HANDOFF_HQ_HOST` is `hq.abra-ca-dabra.app`. Old `/admin` links on the client host open the staff origin. A signed-out visit goes to `/login`. Client records are at `/clients` on that host. Deals are at `/leads` on that host. Moving a deal to won turns a lead into a client and opens a project and a space when they do not have one. Today is `/` on the staff host. Open work is `/work`. A project is `/projects/[id]` with milestones, tasks, and status updates. A client page lists that company's projects. Staff pages use a sidebar. A client page lists people, notes, calls, tasks, and a timeline, and staff can merge two clients. A new file space opens from `/spaces/new`. Local staff pages use `hq.localhost`. `HANDOFF_HQ_ORIGIN` is the absolute staff origin. `HANDOFF_APP_ORIGIN` is the client host used when a staff page links to `/w/[slug]`. A person who belongs to a space can still upload there. Someone on staff who does not belong to the space cannot. The folder owner and the admin can copy a share link so someone else can upload. A member of the folder cannot. R2 bucket `handoff` is in ENAM, the same region as D1. `wrangler.jsonc` binds that bucket as `FILES` for uploads and `BRANDING` for logos. `open-next.config.ts` keeps the dummy incremental cache so Next's cache does not share the bucket with client files. Production uploads write to `FILES`. A local run without that binding still uses `HANDOFF_OBJECT_PATH` (default `.data/objects`). D1 writes that used to send SQL `BEGIN` go out as one `batch()` call, because remote D1 rejects `BEGIN`. The ClamAV container in `worker/Dockerfile` is not part of this deploy, so a finished upload stays `uploaded` until a scan worker that can read R2 is running. The apex `abra-ca-dabra.app` is the marketing Worker `abracadabra-marketing`. It is not attached to this Worker. `check.abra-ca-dabra.app` is Worker `readiness-check`.

`POST /api/intake/assessment` and `POST /api/intake/booking` take a signed JSON body from the Readiness Check. The signature is hex HMAC-SHA256 of the raw body in `X-Intake-Signature`, and `X-Intake-Timestamp` is unix milliseconds. A bad signature, a missing `INTAKE_SIGNING_SECRET`, or a timestamp more than 5 minutes off returns 401. A body that fails the check returns 400. A good body goes on queue `lead-intake` and the route returns 202. Worker `handoff` consumes that queue and writes a lead in D1. Worker `handoff-hq` can enqueue the same queue and does not consume it. A failed write retries, then lands on `lead-intake-dlq`. Set `INTAKE_SIGNING_SECRET` on both workers. Leave it out of git. The check publishes `{ source, payload }` onto queue `lead-intake`. Worker `handoff` consumes that queue. The public client host is `https://handoff.abra-ca-dabra.app`.

`POST /api/github/webhook` is staff-host only. GitHub signs the raw body with HMAC-SHA256 in `X-Hub-Signature-256`. A bad signature, or an empty `GITHUB_WEBHOOK_SECRET`, returns 401. A missing `X-GitHub-Delivery` returns 400. A good body goes on queue `github-events` and the route returns 202. Worker `handoff` consumes that queue and writes a timeline row when the repo is linked to a client. Worker `handoff-hq` can enqueue the same queue and does not consume it. A failed write retries, then lands on `github-events-dlq`. A repeat delivery id is ignored. Set `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY`, and `GITHUB_WEBHOOK_SECRET` on both workers. Leave them out of git. An admin opens `/settings/github` to see the installs. Staff link a repo from the client page.

`GET /api/health` migrates a local database if needed and reports `{ database: "d1", ok, visible }` for a signed-out caller. `visible` is how many workspaces that caller can see. It does not list names or counts of hidden rows.

A super-admin opens a space from `/spaces`, assigns operators from `/spaces/staff`, and sets the file policy and storage limit. An operator invites a client owner or member from `/w/[slug]/people`. A client owner invites members from that page and cannot invite another owner. The invite email is a magic link that returns to `/invites/[inviteId]`. Acceptance creates a membership keyed by the signed-in user id, and only when that user's email matches the invite, the invite is still live, and the workspace is active. A second live invite for the same email is refused, and one person can send 30 invites in a day. Creating a workspace from a template copies that template's items into `requests`. A workspace opened with no file ask starts with one open request named Files, so the share link can take uploads. Later template edits do not change the copy. Staff upload a PNG or WebP logo of at most 512 KB. The server decodes and re-encodes it to PNG before storing it under `.data/branding` (`HANDOFF_BRANDING_PATH` overrides that directory, or the `BRANDING` R2 binding when that bucket exists). The workspace layout shows `display_name` and that logo. A workspace the caller cannot see returns 404. Staff manage request templates at `/spaces/templates`. Operators manage requests at `/w/[slug]/requests`. The workspace home is a shared folder: it lists files, and Upload opens `/w/[slug]/drop`. One open request is used on its own. When several are open, the person picks one so the upload still attaches to that request. `POST /api/workspaces/[slug]/batches` accepts a JSON manifest of paths and sizes, writes `pending` file rows, and returns object keys shaped `{workspaceId}/{batchId}/{fileId}`. The body carries no file bytes. A caller who does not belong to the space cannot create a batch. An admin who belongs to the space can. An archived workspace, a closed or foreign request, a blocked name, an over-quota manifest, and an 11th batch in the same hour are refused. A file with no tag inherits the request's suggested tag, or `other`. `POST /api/batches/[batchId]/files/[fileId]/grant` opens a `pending`, `uploading`, or `failed` file in an active batch and refreshes `last_activity_at`. `POST .../complete` reads the stored object size from local object storage (`HANDOFF_OBJECT_PATH`, default `.data/objects`) and does not accept a size in the body. A matching size marks the file `uploaded`, sets `next_scan_at`, and writes one `file.uploaded` audit. A mismatch marks it `failed`, records the reason, and deletes the object. A repeat completion returns the same row. A caller who does not belong to the space cannot grant or complete. An admin who belongs to the space can. The drop page `/w/[slug]/drop?request=` lets a client member upload a folder or several files. Parts are 6 MiB, three files at a time, through `POST /api/batches/[batchId]/files/[fileId]/multipart` and `PUT /api/objects/parts`. Local bytes land in `HANDOFF_OBJECT_PATH`. Production without that path and without the `FILES` binding answers 503. The page states which files Handoff accepts and links to `/how-handoff-handles-files`. The workspace home lists files in that folder. The person who uploaded a file can delete that file, or a folder of files they uploaded. Deleted files leave the list and cannot be downloaded. The bytes are removed. A file that was still checking is marked failed so it is not scanned. Someone else in the folder cannot delete those files. Staff open a file's details at `/w/[slug]/batches/[batchId]`. `/w/[slug]/batches/[batchId]` shows each file's path, size, tag, status, and hash, and marks a file that matches an earlier clean file in the same workspace. A clean file download is a 5-minute HMAC attachment URL signed with `HANDOFF_SIGNING_SECRET`. A missing secret answers 503. Held, scanning, and rejected files are not downloadable. A client discards their own batch only while no file is clean. Operators change tags from that screen. `GET /api/batches/[batchId]/export` returns JSON for one batch. Clean files include a 60-minute HMAC URL. Held, rejected, and failed files are listed without a URL. A client receives 403, a caller outside the workspace receives 404, and the 21st export by that operator in an hour receives 429. The audit row records counts only. `npm run pull -- export.json ./out` recreates the tree, checks each SHA-256, skips a file that already matches, and refuses a path that would leave the target directory. A hash mismatch deletes that partial file and exits non-zero. A super-admin reviews held files at `/spaces/held`. Release marks the file `clean`, stores the written reason, emails the uploader, and can mark the named request received. Reject marks the file `rejected` and emails the uploader without receiving the request. An operator or client receives 403. A caller who cannot see the file receives 404. A blank reason receives 422. Archiving an active workspace sets `purge_after` to the archive time plus `retention_days`, refuses new batches, invites, and requests, and keeps downloads. Owners and operators are emailed with the purge date. A reminder is queued when purge is within 7 days. A super-admin downloads every batch as JSON from settings. Clean files include a 24-hour HMAC URL. The audit records counts only. Purge refuses an active workspace. An early purge requires a super-admin and a written reason. Purge deletes object bytes and the file, batch, request, invite, and membership rows, marks the workspace `purged`, and keeps the audit.

People in a space can preview a picture, a PDF, or a text file while it is still checking. HTML and SVG are not shown. Preview uses the signed-in session at `GET /api/files/[fileId]/preview` (`Content-Disposition: inline`, `nosniff`, and a locked-down content security policy). Download stays closed until the file is `clean`. The owner or an admin can read the words in text and PDF files through Cloudflare AI Gateway (`HANDOFF_AI_GATEWAY_ID`, default `default`). Notes are written with `@cf/meta/llama-3.2-3b-instruct`. Passages are embedded with `@cf/baai/bge-base-en-v1.5`. Notes and passages stay in D1 for that space only. A deleted file drops out of the list and out of search. Pictures are skipped. If the Worker `AI` binding is missing and the local account id or API token is missing, Read files marks text as waiting and does not invent a summary. Make a project key shows a bearer token once. A client project sends `POST /api/mcp` with that token to search or list the read files. The token is stored as a SHA-256 hash. A space can have five live keys.

## Writing style

All text people see (screens, emails, error messages) is written in short, plain sentences at about a grade 5 reading level. Say "space" (not workspace or locker), "storage limit" (not quota), "admin" (not super-admin) and "delete" (not purge). Code names, routes, status values and database fields keep their technical names.
